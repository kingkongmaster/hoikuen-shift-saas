## 契約状態と権限

`verifyContract`を契約の共通判定にする。Tenant一致、既知Plan／status、整数上限1〜1000、
有効な開始・終了日時、開始≦現在＜終了、Plan/statusの整合を必須とする。
有料契約の期間未設定、PAST_DUEの書込み猶予は廃止した。

| 実効状態 | 表示 | 業務機能 |
|---|---|---|
| TRIAL | 試用中 | 試用プランの権限 |
| ACTIVE | 契約中 | 現プランの権限 |
| CANCELLATION_SCHEDULED | 解約予定 | 終了時刻までは現プラン |
| EXPIRED | 期限切れ | 拒否 |
| CANCELLED | 解約済み | 拒否 |
| SUSPENDED | 利用停止 | 拒否。運営者のみ再開 |
| PAST_DUE | 支払確認中 | 拒否 |
| UNVERIFIED | 契約情報の確認が必要です | 拒否 |

有効な契約がなければ、業務APIの取得・変更とも拒否する。本人セッション確認 `/me`、
契約状態 `/subscription/access`、園ADMIN契約メタデータ、Feature一覧のみ例外。
不正契約では契約詳細・Feature一覧も403とし、accessはUNVERIFIEDを返す。
ログイン自体を解約と同時に削除しない。Webは契約案内・ログアウト・サポートへ進める。
認証の初回パスワード変更等は既存の本人認証制御を維持する。
運営ルートは園契約を必要としないが、既存の運営者専用認可と所属検証を必須とする。

## TRIALと機能表

初回はprovision APIが30日、上限20名のTRIALを原子的に作成。期限後の自動有料化なし。
期限切れは参照時に導出するため、定期ジョブの遅延で有料機能が開くことはない。
運営者による明示的な延長は既存機能を再利用。未終了なら旧終了日から、終了済みなら現在から延長する。

| 機能／上限 | TRIAL | STANDARD | PROFESSIONAL |
|---|---|---|---|
| 初期職員上限 | 20 | 50 | 200 |
| シフト自動生成 | 可 | 可 | 可 |
| 高度な勤務パターン | 不可 | 不可 | 可 |
| 個別勤務条件 | 不可 | 不可 | 可 |
| 役職・資格管理 | 不可 | 不可 | 可 |
| 詳細必要人数 | 不可 | 不可 | 可 |
| 園専用ルール | 個別明示許可のみ | 個別明示許可のみ | 個別明示許可のみ |

全プランで基本の職員・部署・標準勤務パターン・必要人数・希望休・有給・月次・印刷を利用する。
表は既存Feature catalogを維持した実装仕様。料金・最終販売パッケージの決定ではない。
明示的なTenant Feature overrideは既存優先順位を維持するが、契約失効を上書きできない。
未知source、不正期間、Tenant不一致のoverrideは閉じる。期限切れoverrideはプラン既定へ戻る。
職員上限の個別変更は運営者、理由、設定元を必須とし監査する。上限を下げても職員は削除しない。

## 更新・変更・解約・停止

`PATCH /platform/tenants/:tenantId/subscription` が唯一の既存運営更新入口。
有料開始・期間更新・プラン変更・ACTIVEへの再開では、開始／終了期間と
`confirmationReference`（確認済み契約の参照）を必要とする。
これは運営者の手動確認記録であり、自動決済証明ではない。園ADMINには更新権限を与えない。
Tenant行ロックで解約申請と運営変更を直列化し、更新とAuditを同一transactionにする。
従来のPLAN_CHANGED、TRIAL_EXTENDED、TENANT_SUSPENDED、TENANT_REACTIVATED、
STAFF_LIMIT_OVERRIDE_UPDATED等の監査区分を維持する。

園ADMINは `POST /subscription/cancel-request` で理由を付け期間末解約を予約できる。
既存 `cancelledAt` を**利用終了の実効日時**として使う。未来日時＋有効statusなら解約予定、
日時到達後はCANCELLED。予約受付時刻はAuditに残す。新規enum／Migrationは不要。
運営者は予約取消・明示的な即時解約も扱える。再契約は新しい有効期間と確認参照、予約取消で再開する。

SUSPENDEDは解約予約とは別。停止理由・停止日時を記録し、期間経過だけでは解除しない。
園ADMIN／一般職員による解除不可。停止後もログインは本人と契約案内の確認に限定する。
解約・停止・期限切れで職員、勤務、休暇、監査データを自動削除しない。
保持期間、削除の申請／承認／バックアップからの消去、法務要件の最終値は**要販売／法務判断**。
このPhaseでは削除jobも保持期間定数も追加しない。

## ダウングレード

全データを保持し、有効契約内では対象機能の既存設定を読み取り専用で参照できる。
利用不可になったactiveな独自勤務パターン／個別勤務条件／詳細必要人数が残る場合、
Setup HARD「保存済み勤務条件と契約の整合」を未完了にする。
作成・生成・生成前確認・手動変更・FINALも契約条件不整合を拒否する。
勤務条件を黙って除外すること、条件を自動無効化／削除することはしない。
解消は運営者によるプラン復帰または確認済み個別機能許可。不要条件の見直しは利用可能な権限下で園が明示操作する。

## Web

既存 `/#operator` の導入画面へ契約管理を追加。Tenant、Plan、状態、試用期限、契約期間、
解約日、職員上限を確認し、変更・更新・停止・試用延長を操作できる。職員個票は表示しない。
既存園ADMIN「契約情報」に終了日、利用不可機能、解約予約を追加。権限表はAPIのFeature判定を表示する。
ContractGateは取得失敗も閉じ、30秒間隔・ウィンドウfocus・契約拒否応答で再取得する。
契約変更時は業務画面を再読込して古い機能表示を残さない。通信中の画面表示よりAPI認可を常に優先する。
