# 日本の休日とDRAFTの確認

日曜、日本の祝日・振替休日・国民の休日は標準休園、土曜は原則開園。
休日データは内閣府の公表CSVを固定収録し、出典・取得日・SHA256をソースに記録する。
対応範囲は1955〜2027年。未公表の将来年は予測せず、生成・FINALを停止する。
更新時は内閣府 https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html の公表年とCSVを照合する。

日付指定の特別開園/休園 > 園独自休園 > 日本の標準休日・日曜 > 通常の曜日設定。
旧曜日設定の日曜開園を、全ての日曜を自動的に特別開園する指定へ昇格させない。
土曜休園設定は休日でない土曜に適用する。行事の登録だけでは開園指定にならない。

特別開園/休園は既存TenantRuleExceptionのCALENDAR_DAYに保持する。
同日競合は409で拒否し、解除して再指定する。TenantClosedDateと休日マスターは保持する。
管理者・園長のみ書込み可能。一般職員は実効カレンダーの読取りのみ可能。

1. カレンダーを確認する（日曜・祝日・独自休園・特別開園）。
2. 園行事を確認する。
3. 園・職員の勤務条件、固定勤務、必要人数を確認する。
4. 希望休・勤務希望と提出状況を確認する。
5. 有給残数・取得予定・半休を確認する。
6. 未提出・不足・矛盾を生成前チェックで確認する。0件提出と未提出は別。
7. DRAFTを生成する。自動生成は既存DRAFTの置換操作なので管理者確認を必須とする。
8. 手動調整と明示的再評価で現在条件との整合を確認する。
9. FINAL後、印刷・職員共有へ進む。

条件変更・休園登録による自動再生成や割当の自動修正は行わない。
月間表を開く/「表示を更新」で最新条件の影響日と休園日の勤務を表示する。
対象セルを個別修正、または根拠のある特別開園を設定し、提出確認と再評価を行う。
再評価POSTは監査receiptのみ記録し割当を変えない。GET閲覧で承認済みにはしない。
条件と割当のfingerprintが再評価時と一致しなければFINALを拒否する。
FINALは最新条件をserializable transactionでも再検証し、休園勤務等のHARDを拒否する。
特別開園でも勤務禁止・休暇・必要人数等の既存防御は残る。

既存DRAFTには再評価receiptがないため、初回に明示再評価が必要になる。
印刷は実効休園・特別開園を表示し、A4/B4/A3を選択できる。既定B4は維持する。
PWAはAPIをキャッシュしない。未保存編集がある間は表示更新・再評価を無効化する。

Security修正は別commit。JSONは10MB上限、圧縮JSONは415、不正JSONは400、超過は413。
フォーム入力は既存どおり対応対象外（400）。認証・Tenant境界は変更しない。
schema/migrationおよびgenerator本体の変更はない。

検証: `security-input.e2e.cjs`, `holiday-calendar.e2e.cjs`, `holiday-calendar-ui.e2e.cjs`。
必ずTEST_DATABASE_ISOLATED=trueと、localhostのtest/isolated名DBを使用する。
UI検証は実API/DBとビルド済みWebに接続し、EVIDENCE_DIRへ匿名の画像・PDF・結果を保存する。
Productionや正式データをfixtureに使用しない。
