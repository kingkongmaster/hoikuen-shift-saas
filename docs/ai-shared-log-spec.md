# AeN Shift AI共用ログ運用仕様

制定日: 2026-08-17

## 目的

特定AIや特定チャットだけに重要知識を閉じ込めず、別のAIがこのログを起点にGitHub、正式仕様、監視ログを確認し、現在状態と次の行動を再現できるようにする。

## 記録対象

原則として、仕様判断、実装、監査、障害調査、セキュリティ確認、migration、deploy、運用変更、重要テストを1作業1記録とする。雑談、重複説明、長大な生ログは保存しない。

## 必須項目

- 日時
- 作業IDまたは簡潔なタイトル
- 対象branch
- 対象commit
- 対象環境
- 作業目的
- 変更内容
- 仕様判断
- テスト結果
- 発見した問題
- 原因
- 対応
- 未解決事項
- 次の推奨作業
- 人間承認が必要な事項

branchやcommitを確認できない場合は推測せず「確認不能」とし、その理由を記録する。

## 参照と役割分担

- 開発日誌には、人間が読みやすい経緯、成果、判断理由を簡潔に記録する。
- AI共用ログには、機械が引き継ぎやすい事実、状態、判断、参照先を構造化して記録する。
- 同じ長文を二重保存せず、相互リンクを使用する。
- コードの事実はGitHubのbranch / commit / PRを参照し、ログ本文へコード全文を貼らない。
- 本番の事実は監視システム上の期間、event ID、dashboard等を参照する。

## 禁止情報

- password
- token、Cookie、Authorizationヘッダー
- API secret、秘密鍵、DB接続文字列
- 不要な職員氏名、住所、連絡先、健康情報
- 長大なコマンド生ログやDBダンプ

誤って含まれた場合は、アクセス制限、削除・伏字化、秘密情報の失効・再発行を人間承認の下で行い、事象だけを安全に記録する。

## 状態表現

各記録は「完了」「一部完了」「未着手」「ブロック」「人間承認待ち」を明確にする。検証していない事項を完了扱いにしない。正式DBへ接続していない監査では、その事実を必ず明記する。

## Notion構造

Notion「AI共用ログ」をAI間の正式な共通情報源として使用する。1行を1作業、ページ本文を詳細記録とし、タイトル、日時、branch、commit、環境、状態、人間承認要否を一覧で確認できるようにする。残りの項目はページ本文へ定型見出しで保存し、他AIがこの記録から確認先と次の作業を判断して継続できる構造にする。
