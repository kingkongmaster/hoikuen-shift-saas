# AeN Development Memory（ADM）

ADM Version: v1.0

## 目的

AeN Shiftを含むアプリ開発の経験を、次の設計・実装・検証・障害対応で再利用できる知識として残します。人とLLMが同じ根拠を参照し、同じ失敗を繰り返さないための最小基盤です。

## 基本運用

作業前に関連するNotionログとGitHub履歴を確認し、過去の判断・失敗・検証方法を再利用します。作業後は新しい知見だけを簡潔に記録し、詳細な変更履歴はGitHubへ委ねます。

ADMへ記録する前に、30〜60秒で次の3項目を判断します。

1. 再発する可能性があるか
2. 他の製品でも再利用できるか
3. 将来のLLMや開発者の判断材料になるか

いずれか1つでも「YES」なら記録し、すべて「NO」なら記録しません。これにより「最小の記録で最大の再利用価値」を維持します。

## Notionの役割

「アプリ開発ログ」を、目的・原因・検証・再発防止を検索できる知識ベースとして扱います。GitHubの差分だけでは分からない判断の背景や知見を保存します。

## GitHubの役割

コード、文書、Commit、PR、レビューを正確な変更履歴として保存します。Notionから関連CommitやPRへたどれる状態を保ちます。

## ChatGPTの役割

要望整理、設計相談、説明、過去知見の要約を支援します。不明点を推測で確定せず、判断材料と選択肢を分かりやすく示します。

## Codexの役割

NotionとGitHubの根拠を確認し、最小差分で実装・検証・記録します。結果だけでなく、原因、確認方法、再発防止へつながる知見を残します。

## 将来のローカルLLMの役割

NotionログとGitHub文書を検索し、過去の経験を設計・実装・障害対応へ再利用します。機密性を保ちながら、組織固有の判断を支援します。

## アプリ開発ログ 最小テンプレート

### 目的

この作業で解決する課題と、必要になった理由を書く。

### 実施内容

変更・調査した対象と、行ったことを簡潔に書く。

### 検証方法

実行したテスト、確認画面、使用環境を書く。

### 結果

PASS／FAIL、完成範囲、未解決事項を書く。

### 原因（必要時）

問題が起きた直接原因と、見落とした条件を書く。問題がなければ省略する。

### 回避・改善

実施した修正と、次回の確認点を書く。

### 再利用できる知見

AeN Shift固有か、他のアプリにも適用できるかを明記する。

### 関連Commit

Commit Hashと要約を書く。未Commitなら「未実施」と書く。

### 関連PR

PR番号とURLを書く。未作成なら「未実施」と書く。
