# むすび保育園 Windows試供版 提供方式比較

## 目的と前提

2026年9月の試用開始を目標に、むすび保育園のWindows PCで園シフトを安全かつ簡単に起動する方法を比較する。現地PCの性能、Windows状態、インターネット品質、バックアップ状況の確認後に正式決定する。

現時点の第一候補は、**B. 軽量起動アイコン＋クラウド型**である。これはクラウド契約、正式DB、運用開始を決定したという意味ではない。

## 比較する3方式

### A. 完全ローカル型

Web画面、API、PostgreSQL、バックアップ、復元、起動・停止を園のPC内で管理する方式。

### B. 軽量起動アイコン＋クラウド型

園のPCには軽量な起動手段だけを用意し、ブラウザから専用URLへ接続する方式。APIとDBはクラウド側に配置する。

### C. デスクトップラッパー型

現在のWeb画面をElectron等の枠で包み、一般的なデスクトップアプリのように起動する方式。APIとDBの配置は別途決める。

## 比較表

| 比較項目 | A. 完全ローカル型 | B. 軽量起動＋クラウド型 | C. デスクトップラッパー型 |
| --- | --- | --- | --- |
| 古いPCへの負荷 | 高い。API・DBも常時動作 | 低い。主にブラウザだけ | 中～高。Electronは負荷が大きい傾向 |
| 必要メモリ | 多い | 少ない | Bより多い |
| 必要容量 | 数GB以上になりやすい | 起動設定程度 | アプリ本体分が必要 |
| 管理者権限 | 導入・保守で必要 | 不要または初回だけにできる可能性 | インストール時に必要な可能性 |
| インターネット依存 | 低くできる | 高い | API・DBの配置による |
| セキュリティ | 園PCごとの保守が必要 | サーバー側で統一しやすい | PCとサーバー双方の管理が必要 |
| 個人情報保護 | PC紛失・故障・ローカルコピーへ注意 | 通信暗号化、権限、クラウド契約の確認が必要 | 配置方式とローカル保存有無による |
| バックアップ | PCごとに必要 | サーバー側で一元化しやすい | DB配置方式による |
| 復元 | PC故障時に難しい | 別端末から再開しやすい | アプリ再導入とDB復旧が必要 |
| 更新方法 | PCごとに更新 | Web・APIを一括更新 | アプリ配布更新が必要 |
| 障害対応 | 現地対応が増える | 通信とクラウド双方の切分けが必要 | アプリ・通信・サーバーの切分けが必要 |
| 複数端末利用 | 同期設計が難しい | 対応しやすい | APIがクラウドなら対応しやすい |
| スマートフォン利用 | 別構成が必要 | 同じWeb画面を利用可能 | スマホは別途Web利用 |
| 開発工数 | 高い | 比較的低い | 中～高 |
| 保守工数 | 高い | 比較的低い | 中程度 |
| 2026年9月試用への適合性 | 低い | 高い | 中程度 |
| 将来の商品化への適合性 | 導入先ごとの保守負担が大きい | 複数園へ展開しやすい | アプリ体験は良いが配布保守が増える |

必要メモリや容量の具体値は、実装方式と現地PC確認前には確定しない。

## 第一候補Bの想定

- Windows用の軽量セットアップを用意する。
- デスクトップへ「園シフト」アイコンを作成する。
- アイコンからむすび保育園用の専用URLをEdgeまたはChromeで開く。
- APIとDBはクラウド側へ配置する。
- 古いPCへPostgreSQLを導入しない。
- URL、ショートカット、インストーラーへID・パスワード・APIキー等の認証情報を埋め込まない。
- 軽量セットアップはアンインストール可能にする。
- PWAも候補とする。

PWA（Progressive Web App）とは、WebサイトをWindowsのデスクトップやスマートフォンへ、アプリに近い形で追加する仕組みである。

## B方式で決定前に確認する事項

- 現地PCでサポート中のEdgeまたはChromeが動作するか
- 通信が業務時間中に安定しているか
- Webサイトへのアクセス制限がないか
- 利用端末数とスマートフォン利用範囲
- 職員ごとのアカウントと権限
- クラウドサービス利用に対する園側承認
- 個人情報の保管場所、通信暗号化、ログ、保存期間
- バックアップ頻度と復元手順
- インターネット障害時の業務手順
- Windowsアイコン作成・アンインストールの管理者権限

## 2026年9月までの判断手順

1. 読み取り中心の現地PC・通信確認
2. 園側の利用人数、端末、運用方法の確認
3. 個人情報、バックアップ、障害時対応の合意
4. B方式での接続・印刷・スマートフォン試験
5. 問題があればA・CまたはPC更新を再比較
6. 試供版の範囲と終了・データ返却方法を合意
7. 2026年9月の試用開始可否を決定

試用期間は正式運用ではなく、実際の業務で操作性と条件を調整する期間として扱う。
